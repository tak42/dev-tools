# issue を 1 件実装する

1 回の実行で扱う issue は **1 件だけ**。終わったら次の issue に進まずに止まる。

## 手順

1. **対象を決める**
   ID の指定があればそれを使う。なければ `node scripts/issues.mjs next` の先頭行を使う。
   何も出なければ「着手可能な issue はない」と伝えて終わる。

2. **issue を読む**
   `issues/open/<ID>.md` を読む。`parent` があればそのストーリー（`issues/stories/<parent>.md`）も読む。

3. **必要なものだけ読む**
   「コンテキスト」節のファイルと仕様の箇所を読む。それで足りない場合だけ、関連ファイルを最小限に探す。
   読んだ追加ファイルは、後でメモ節に書く（次回以降の issue 作成に活かすため）。

4. **実装する**
   「やること」の範囲だけを変更する。範囲外の改善点を見つけたら、直さずにメモ節へ書く。

5. **検証する**
   frontmatter の `acceptance` のコマンドを実行する。プロジェクトに lint・型チェック・全体テストがあればそれも実行する。

6. **結果を記録する**
   - **成功した場合**: 「やること」と「完了条件」のチェックボックスを埋め、メモ節に要点（変更したファイル、判断したこと、追加で読んだファイル）を数行で書いてから、`node scripts/issues.mjs close <ID>` を実行する。
   - **失敗した、または終わらなかった場合**: close しない。メモ節に、失敗内容・試したこと・残作業を書く。issue が大きすぎたと判断したら、分割案もメモ節に書く。

7. **報告する**
   ユーザーに、issue ID、結果（完了／未完了）、変更したファイル、検証結果を短く報告して止まる。
   コミットは、ユーザーから指示がある場合だけ行う。その場合のメッセージは `<ID>: <タイトル>` で始める。
